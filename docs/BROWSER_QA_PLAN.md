## Execution order and acceptance

1. Save branch/status/source/environment evidence, inspect migrations and test DB isolation; start only required local services.
2. Run the configured Chrome suite unchanged with retained traces and JSON/HTML report. Investigate failures with focused reruns; never weaken business assertions to obtain green.
3. Add focused regression tests for uncovered high-risk conditions. Run additions and critical cross-browser journeys sequentially on clean fixtures; record missing browser binaries as BLOCKED if unavailable.
4. Run unit/provider simulations, existing PostgreSQL integration, isolated workflow/bootstrap tests, lint and typecheck; run production builds with output isolation. Record commands/exit codes.
5. Compare source manifest, inspect screenshots, distinguish product bugs from harness/environment failures and usability/external gaps. Write BROWSER_QA_REPORT with PASS/FAIL/BLOCKED/NOT RUN matrix, reproducible severity-ranked findings and readiness verdict.

Acceptance requires matching order, cash and stock records; recoverable failures; preserved consent; access isolation. Passing browser emulation cannot certify actual-phone usability, live SMS/payments, WhatsApp handoff, closed-app notifications, staging security or backups.
